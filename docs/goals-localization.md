# Goals Library Localization & Validation

Enterprise module for translating an authoritative English Goals Library CSV into a target-language SuccessFactors workbook while preserving structure and enforcing a hard QA gate.

Upload only the English CSV. The SuccessFactors XLSX workbook is generated by copying that CSV structure (no separate template upload). Download the translated workbook after the hard QA gate.

## Route

- Web: `/goals-localization`
- APIs under `/api/v1/goals-localization/*`

## Architecture (two modes)

Toggle on the page / `qa_mode` form field on `POST /jobs`:

| Mode | `qa_mode` | Path |
| --- | --- | --- |
| Classic (default, recommended) | `classic` | Protected terminology → Azure Translator → restore terms → Python numeric/date/terminology QA → Excel rebuild |
| Foundry | `foundry` | Same translation path, plus Azure OpenAI semantic QA and automatic correction |

Classic mode does **not** require Azure AI Foundry. It protects approved glossary terms with placeholders (`BCD` → `__KEEP_001__`), translates the rest, restores terms, then validates numbers, percentages, quarters, dates, and workbook structure in Python. Semantic accuracy still needs human review for ambiguous phrasing.

Configurable preserve list: `app/goals_localization/glossary.py` (`PRESERVE_TERMS`).

## Environment

| Variable | Purpose |
| --- | --- |
| `AZURE_TRANSLATOR_ENDPOINT` | Translator Text API endpoint (required for both modes) |
| `AZURE_TRANSLATOR_KEY` | Translator key (server-only) |
| `AZURE_TRANSLATOR_REGION` | Optional region header |
| `AZURE_OPENAI_*` | Required only when `qa_mode=foundry` (semantic QA / correction) |
| `GOALS_LOCALIZATION_MAX_UPLOAD_MB` | Upload size cap (default 50) |
| `GOALS_LOCALIZATION_TRANSLATE_BATCH_SIZE` | Translator batch size (default 50) |
| `GOALS_LOCALIZATION_MAX_CORRECTION_ATTEMPTS` | Per-field auto-correct limit for Foundry mode (default 2) |

Without Translator credentials, jobs fail at the translation stage with a clear error. Automated tests mock Azure services and do not call live APIs.

## Worker

Outbox event type: `goals.localization.run`

Processed by `services/worker` via `process_localization_job`.

## Local run

1. Ensure Docker Postgres/Azurite are up.
2. `uv run --directory services/api alembic upgrade head`
3. Start API + worker + web as usual.
4. Open `/goals-localization` as a tenant admin / recruiter.
5. Leave **Azure AI Foundry semantic QA** off for classic, or turn it on for Foundry.

## Azure deploy notes

- Add Translator key/endpoint/region secrets to Container Apps (api + worker).
- OpenAI/Foundry secrets are optional unless you enable Foundry mode.
- Ensure blob container `goals-localization` is creatable by the app identity / connection string.
- Do not expose Translator or OpenAI keys to the Next.js bundle.
